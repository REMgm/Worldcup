# WORLDCUP PULSE

Live knockout bracket, match momentum, player form and prediction reveals for the 2026 World Cup. Read-only editorial: **takes, not tips**. Built to the v1 build spec — the tournament is at the knockout stage, so the bracket is the product.

## Stack

- **Next.js 15** (App Router, React 19) — server components by default, client components only for animated islands
- **TailwindCSS v4** — design tokens in `app/globals.css` via `@theme`
- **Framer Motion 12 + canvas-confetti** — all springs/variants centralized in `lib/motion.ts`
- **Supabase (Postgres)** — cache + snapshots, RLS on, anon read-only
- **Vercel Cron → Next route handlers** — match-window-aware schedule

## Architecture (the three locked decisions)

1. **Single data provider.** Exactly one adapter is active at runtime behind the `FootballProvider` interface (`lib/providers/`). With zero keys configured the default is the **keyless ESPN World Cup feed** (near real-time, unofficial/undocumented — mapped defensively). Setting `API_FOOTBALL_KEY` makes API-Football the default (the spec's primary); `PROVIDER=espn|api-football|football-data` forces an adapter explicitly.
2. **Cache-first, never client-polling.** All provider calls happen server-side on Vercel Cron into Supabase. The client reads only from Supabase or ISR-cached route handlers (`/api/live`, revalidate 30). The `LiveTicker` island polls our own edge, never the provider.
3. **Photoreal world, caricature players.** Environments are photoreal; players render as exaggerated caricatures (Spitting Image register) stored in `players.stylized_url`. Licensed provider photos are the fallback while the caricature queue drains. Near-photo AI likenesses of named athletes are excluded — if a render could be mistaken for a photograph, it fails QA.

### Demo mode

When Supabase env vars are missing (or the cache is empty), the app renders from a bundled demo dataset (`lib/demo.ts`) — fictional knockout results with relative kickoffs so one match is always live. A `DEMO DATA` badge shows on the home page. Add real keys and run the daily cron to go live.

## Environment variables

| Var | Purpose |
|---|---|
| `API_FOOTBALL_KEY` | api-sports.io key — optional; presence makes API-Football the default provider |
| `FOOTBALL_DATA_TOKEN` | football-data.org fallback, optional |
| `PROVIDER` | force an adapter: `espn` (keyless default), `api-football`, `football-data` |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon key (RLS read-only) |
| `SUPABASE_SERVICE_ROLE_KEY` | server-only, cron ingest |
| `CRON_SECRET` | protects `/api/cron/*`; Vercel sends it automatically on cron invocations |

Copy `.env.example` → `.env.local` for local dev.

## Data & cron schedule (`vercel.json`)

| Route | Spec schedule (§4) | Job |
|---|---|---|
| `/api/cron/daily` | 06:00 UTC | fixtures next 7 days, top scorers, form snapshots, hot-take regeneration; resolves + pins league/season on first run |
| `/api/cron/odds` | 08:00 & 16:00 UTC | odds snapshots for fixtures in the next 48h, append-only for movement charts |
| `/api/cron/live` | every minute, 15:00–23:59 UTC | exits with **zero provider calls** unless a cached fixture is LIVE or kicking off ±10 min |

All cron routes require `Authorization: Bearer $CRON_SECRET`. Provider request counts are logged to the `config` table daily with a warning at 80% of the free-tier budget (100 req/day).

> **Vercel plan note:** Hobby rejects sub-daily cron (deployment fails), so the committed `vercel.json` runs `daily` + `odds` once a day. The full spec schedule lives in `vercel.pro.json` — swap it in on a Pro plan. For live coverage on Hobby, enable `.github/workflows/live-cron.yml` (set repo variable `LIVE_CRON_ENABLED=true` plus `APP_URL`/`CRON_SECRET` secrets); it hits `/api/cron/live` every 5 minutes during the match window, and the route's guard still makes zero provider calls when nothing is live.

## Supabase

Schema lives in `supabase/migrations/20260702000000_init.sql` (tables: `config`, `teams`, `fixtures`, `players`, `player_form`, `odds_snapshots`, `hot_takes`; RLS on, anon `select` only). Two pragmatic additions to the spec schema: `fixtures.elapsed` (live minute for the ticker) and a `hot_takes (fixture_id, headline)` unique constraint so cron regeneration upserts instead of duplicating.

Hot takes are generated by a deterministic rules engine (`lib/takesEngine.ts`) over form + odds deltas — market walk-backs, coin flips, xG overperformance, form spikes. No LLM in the hot path.

## Deploy

Push to the production branch on Vercel (verify the branch mapping/casing before the first deploy — known footgun), set the env vars above, then hit `/api/cron/daily` once with the bearer secret to seed the cache.

## Compliance notes

- Odds are editorial context ("market says 68%"), never betting CTAs. No affiliate links, no bookmaker logos, no "bet now" verbs.
- `prefers-reduced-motion` disables confetti, loops and count-ups globally; the site is fully functional with animations off.
